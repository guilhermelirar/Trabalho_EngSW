# Sistema de Gerenciamento de Backlog

## Visão

### 1. Introdução

A solução proposta consiste em uma aplicação web voltada para o gerenciamento
ágil de requisitos de software por meio de histórias de usuário vinculadas a um
backlog de sprint e de produto. Os principais elementos da soluão incluem:

- **Módulo de Gestão de Usuários:** parte responsável pela criação de novos usuários
  e controle de acesso seguro por contas e perfis
- **Gerenciador de Hierarquia do Backlog**: estruturação de proejtos, épicos, backlogs
  de sprint e de produto.
- **Módulo de User Stories**: criação de histórias de usuário no formato 
  "Como... Quero... Para..." e dos seus critérios de aceitação no formato 
  "Dado.. Quando.. Então"
- **Mecanismo de Priorização e Estimativa**: ferramentas para atribuição de Story 
  Points, técnicas MoSCoW e cálculo automatizado de RICE Score.

### 2. Posicionamento

#### 2.1 Declaração de Problema

| Campo                            | Descrição              |

| **O problema**                   | da e falta de padronização na gestão de requisitos e priorização |
| **Afeta**                        | gerentes de produtos (POs), scrum masters, analistas de requisitos e equipes de desenvolvimento que trabalham com user stories e sprint backlogs |
| **O impacto é**                  | histórias de usuário mal estruturadas, estimativas imprecisas, e priorização subjetiva de tarefas|
| **Uma solução de sucesso seria** | um sistema centralizado para forçar o uso dos padrões formais de User Stories e critérios de aceitação, e automatize o cálculo de métricas RICE |

#### 2.2 Declaração da Posição do Produto

| Campo                     | Descrição                                   |
| :------------------------ | :------------------------------------------ |
| **Para**                  | Equipes de desenvolvimento de software e gerentes de projeto                          |
| **Que**                  | necessitam gerenciar requisitos e priorizar backlog de forma padronizada e ágil |
| **O `Sistema de Gerenciamento de Backlog`** | é uma plataforma de gerenciamento de requisitos                           |
| **Que**                   | fornece padronização de User Stóries e critérios de aceitação e estrutura ordenação de backlog por meio de algoritmo RICE Score e métrica MoSCoW          |
| **Ao contrário de**       | ferramentas genéricas de gerenciamento de tarefas, as quais geralmente não possuem validação nativa dos formatos formais de engenharia de requisitos           |
