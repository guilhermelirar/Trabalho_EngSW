# 08 — Protótipo do sistema

## 1. Introdução

Este documento apresenta a implementação do front-end do sistema Backlog Manager, descrevendo as tecnologias utilizadas, a organização dos arquivos, a estrutura das páginas, os componentes visuais e as principais interações disponibilizadas ao usuário.

O objetivo é documentar como a interface gráfica foi construída e como ela permite que os usuários acessem e utilizem as funcionalidades do sistema. O escopo deste documento está restrito à camada de apresentação, não abrangendo detalhes internos da implementação do back-end ou do banco de dados.

## 2. Tecnologias utilizadas

O front-end foi desenvolvido utilizando tecnologias web, com separação entre a estrutura das páginas, a apresentação visual e as interações executadas no navegador.

As principais tecnologias e recursos utilizados são:

- **HTML5:** utilizado para estruturar o conteúdo das páginas, organizar formulários, campos de entrada, botões, tabelas e demais elementos da interface.
- **CSS3:** utilizado para definir a identidade visual do sistema, incluindo cores, tipografia, espaçamentos, dimensões, alinhamentos e adaptação dos elementos a diferentes tamanhos de tela.
- **JavaScript:** utilizado para implementar interações dinâmicas na interface, como atualizações de elementos, comportamentos de componentes e cálculos relacionados à priorização de histórias.
- **Jinja2:** mecanismo de templates utilizado para gerar as páginas HTML a partir de modelos reutilizáveis, permitindo a composição de elementos comuns e a exibição de informações fornecidas pela aplicação.
- **Google Fonts (Inter):** recurso utilizado para disponibilizar a tipografia empregada na interface.

A aplicação utiliza renderização de páginas por meio de templates, não sendo estruturada como uma Single Page Application (SPA). A navegação entre as principais funcionalidades ocorre por meio de páginas e formulários HTML tradicionais.

## 3. Organização dos arquivos

Os arquivos relacionados à interface estão organizados principalmente nos diretórios de templates e arquivos estáticos da aplicação.

### 3.1. Templates HTML

Os templates são responsáveis pela estrutura das páginas e pela composição dos componentes visuais.

| Arquivo | Responsabilidade |
|---|---|
| `base.html` | Define a estrutura-base das páginas e os elementos compartilhados da interface. |
| `login.html` | Apresenta a tela de autenticação do usuário. |
| `cadastro.html` | Apresenta o formulário de cadastro. |
| `register.html` | Template complementar relacionado ao fluxo de registro. |
| `painel.html` | Apresenta o painel principal do sistema. |
| `projects.html` | Exibe a listagem de projetos disponíveis ao usuário. |
| `project_detail.html` | Apresenta os detalhes de um projeto e suas funcionalidades de gerenciamento de backlog. |
| `_mensagens.html` | Componente reutilizável para exibição de mensagens ao usuário. |
| `_story_card.html` | Componente reutilizável para representação visual de histórias de usuário. |
| `_story_prioritization_fields.html` | Agrupa campos utilizados nos mecanismos de priorização das histórias. |

A utilização de templates reutilizáveis reduz a duplicação de código e facilita a manutenção da interface. Elementos compartilhados podem ser definidos uma única vez e utilizados em diferentes páginas.

### 3.2. Arquivos CSS

Os estilos da aplicação estão separados em arquivos específicos, permitindo organizar a apresentação visual de acordo com as áreas do sistema.

| Arquivo | Responsabilidade |
|---|---|
| `base.css` | Define estilos gerais e elementos compartilhados da aplicação. |
| `components.css` | Reúne estilos de componentes reutilizáveis da interface. |
| `login.css` | Define a apresentação visual da tela de autenticação. |
| `cadastro.css` | Define os estilos específicos da tela de cadastro. |
| `projects.css` | Concentra estilos relacionados às telas de projetos e ao gerenciamento de histórias. |

Essa separação facilita a identificação e a alteração dos estilos, contribuindo para a organização e a manutenção do código.

### 3.3. Arquivos JavaScript

O arquivo `projects.js` concentra as interações dinâmicas relacionadas às funcionalidades de gerenciamento de projetos e histórias de usuário.

Entre suas responsabilidades estão os comportamentos associados aos componentes da página de projetos e os cálculos dinâmicos utilizados nos mecanismos de priorização, conforme os recursos implementados na interface.

### 3.4. Recursos gráficos

A aplicação também utiliza arquivos SVG para representar a identidade visual do sistema, incluindo os arquivos `logo.svg` e `logo2.svg`.

Esses recursos são utilizados na composição visual das páginas, contribuindo para a padronização da interface.

## 4. Estrutura das páginas

A interface foi organizada de modo a separar os principais fluxos de utilização do sistema.

### 4.1. Tela de autenticação

A tela de autenticação permite que o usuário informe suas credenciais para acessar o sistema.

Sua estrutura contempla campos de entrada para os dados de autenticação, botão de envio e elementos visuais relacionados à identidade do Backlog Manager.

### 4.2. Tela de cadastro

A tela de cadastro disponibiliza um formulário para inserção das informações necessárias à criação de uma conta.

Os campos são organizados de maneira a orientar o preenchimento e facilitar a utilização do sistema por novos usuários.

### 4.3. Painel principal

O painel principal funciona como ponto de acesso às funcionalidades da aplicação, permitindo que o usuário visualize e acesse as áreas disponíveis.

### 4.4. Listagem de projetos

A página de projetos apresenta os projetos disponíveis ao usuário, organizados visualmente para facilitar sua identificação e seleção.

A interface utiliza componentes visuais para representar os projetos e disponibilizar as ações relacionadas ao seu gerenciamento.

### 4.5. Detalhamento do projeto

A página de detalhamento reúne as funcionalidades de gerenciamento das histórias de usuário de um projeto.

Sua interface organiza as informações em áreas distintas, permitindo visualizar e manipular elementos do Product Backlog e dos Sprint Backlogs, além de acessar recursos relacionados às histórias, épicos e priorização.

## 5. Componentes e elementos de interface

A interface utiliza componentes visuais para padronizar a apresentação das informações e facilitar a interação do usuário.

Entre os principais elementos implementados estão:

- **Cartões de histórias de usuário:** utilizados para apresentar individualmente as histórias e suas informações relevantes.
- **Abas de navegação:** permitem alternar entre diferentes áreas de gerenciamento do projeto.
- **Formulários:** utilizados para cadastrar, editar e enviar informações relacionadas aos recursos do sistema.
- **Modais:** utilizados para apresentar determinadas operações e interações sem exigir a navegação para outra página.
- **Mensagens de retorno:** apresentam informações ao usuário sobre o resultado de determinadas operações.
- **Elementos de priorização:** permitem visualizar e informar dados utilizados na classificação das histórias de usuário.
- **Elementos relacionados aos épicos:** auxiliam na organização das histórias conforme seus agrupamentos funcionais.

A reutilização desses componentes contribui para manter a consistência visual e comportamental entre as diferentes áreas do sistema.

## 6. Interações e funcionalidades no navegador

Além da estrutura HTML e da apresentação definida pelos arquivos CSS, o front-end utiliza JavaScript para oferecer comportamentos dinâmicos em determinadas funcionalidades.

Entre as interações implementadas, destacam-se:

- Atualização dinâmica de elementos da interface relacionados à priorização de histórias.
- Cálculos associados ao método RICE, considerando os valores informados nos respectivos campos.
- Interações com componentes de navegação e elementos de gerenciamento de projetos.
- Comportamentos de abertura, fechamento e utilização de componentes modais, quando aplicável.
- Apoio à interação com os cartões e campos de informações das histórias de usuário.

As operações convencionais de envio de dados utilizam formulários HTML, seguindo o fluxo de requisição e resposta da aplicação. Dessa forma, as interações dinâmicas executadas no navegador complementam a navegação tradicional, sem substituir a estrutura de renderização das páginas.

## 7. Apresentação visual e responsividade

A apresentação visual do Backlog Manager é definida por folhas de estilo CSS, que estabelecem padrões de cores, tipografia, espaçamentos, dimensões e organização dos componentes.

A separação dos estilos em arquivos específicos permite que elementos compartilhados mantenham uma aparência consistente, enquanto telas particulares podem apresentar características próprias.

A interface também considera a adaptação dos elementos a diferentes dimensões de tela, buscando preservar a organização e a legibilidade das informações em diferentes dispositivos.

## 8. Considerações sobre a implementação

A implementação do front-end do Backlog Manager foi estruturada a partir da utilização de templates HTML, estilos CSS e recursos JavaScript, mantendo uma separação entre estrutura, apresentação e interatividade.

A adoção de templates reutilizáveis favorece a manutenção e a padronização das páginas, enquanto a divisão dos arquivos de estilo permite organizar a identidade visual do sistema. O JavaScript complementa essa estrutura ao implementar interações que exigem atualização dinâmica de elementos da interface.

A documentação apresentada descreve a camada de apresentação do sistema e deve ser considerada em conjunto com os demais artefatos do projeto, especialmente o documento de visão, as histórias de usuário, os requisitos não funcionais e o caderno de arquitetura.
